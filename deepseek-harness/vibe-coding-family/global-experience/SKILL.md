# 跨项目经验沉淀（Global Experience）

**核心思想**：经验分两层——**项目内**（snapshot-notes 管，随项目走）和**跨项目**（本 skill 管，全局共享）。
跨项目经验是"踩过的坑下次所有项目都避开"的可复用资产。

```
经验分层：
├── 项目内快照  .snapshots/SNAPSHOT.md   → 这个项目到哪了（snapshot-notes）
├── 个人工位    agents/<角色>/EXPERIENCE.md → 这个Agent的坑（agent-ops）
└── 全局经验库  ~/.hermes/experience/      → 所有项目共享的坑与模式（本 skill）🆕
```

## 📁 全局经验库结构

```
~/.hermes/experience/
├── INDEX.md                    # 经验索引（按标签分类，检索入口）
├── pitfalls/                   # 踩坑记录（按技术域分类）
│   ├── python.md               #   Python 坑
│   ├── docker.md               #   Docker 坑
│   ├── deploy.md               #   部署坑
│   └── ...（按需新增）
└── patterns/                   # 成功模式（可复用做法）
    ├── project-structure.md    #   项目结构模式
    ├── testing.md              #   测试模式
    └── ...（按需新增）
```

## 📝 经验条目模板（PITFALL，v1.1 加质量评分）

```markdown
## [2026-08-06] Python 依赖冲突（pip resolver）
- **技术域**：Python / 依赖管理
- **项目**：<项目名>（可留空表示通用）
- **坑**：requirements.txt 里有相互冲突的版本
- **症状**：pip install 报 resolver 错误
- **根因**：A 需要 B<2.0，C 需要 B>=2.0
- **解法**：用 venv 隔离 + `pip install --upgrade pip` + 检查上游依赖
- **可复用**：✅（所有 Python 项目适用）
- **effectiveness_score**：0.9   ← v1.1 新增（0~1，越高越有效）
- **验证次数**：3               ← v1.1 新增
- **状态**：active              ← active / deprecated（低分自动归档）
- **TTL**：365d                ← v1.2 新增（到期标记"需验证"，验证通过续期）
```

## 📝 经验条目模板（PATTERN，v1.1 加质量评分）

```markdown
## [2026-08-06] 项目目录结构（src/ 布局）
- **技术域**：项目结构
- **模式**：src/<pkg>/ + tests/ + docs/ 分离
- **为什么好**：避免 import 混乱、测试路径清晰
- **适用场景**：Python/TS 中大型项目
- **已验证**：✅（3 个项目中有效）
- **effectiveness_score**：0.85   ← v1.1 新增
- **验证次数**：3                  ← v1.1 新增
- **状态**：active
- **TTL**：365d                ← v1.2 新增（到期标记"需验证"，验证通过续期）
```

## ⭐ 质量评分机制（v1.1 新增）

**目的**：防止经验库变成"垃圾场"——低分经验自动归档，只留高价值。

### 评分规则（主Agent 在任务完成后自动评估）

| 维度 | 满分 | 评分标准 |
|------|:---:|----------|
| 解法有效性 | 0.4 | 直接解决了问题（0.4）/ 部分解决（0.2）/ 无效（0） |
| 可复用广度 | 0.3 | 跨项目通用（0.3）/ 单项目内可复用（0.15）/ 一次性（0） |
| 信息完整度 | 0.2 | 有根因+解法+症状（0.2）/ 缺一项（0.1）/ 只有结论（0.05） |
| 证据强度 | 0.1 | 有验证输出（0.1）/ 经验判断（0.05） |

**评分流程**：
```
1. 经验入库时：主Agent 按四维打分，effectiveness_score = 四维之和（0~1）
2. 每次成功复用：验证次数 +1，effectiveness_score 微调 +0.05（上限 1.0）
3. 每次复用失败：验证次数 +1，effectiveness_score -0.2
4. 定期维护（每月）：score < 0.3 或 deprecated 标记 → 移入 archive/
```

### 归档标准

| 条件 | 动作 |
|------|------|
| effectiveness_score < 0.3 | 自动归档（移入 ~/.hermes/experience/archive/） |
| 连续 3 次复用失败 | 标记 deprecated → 下次维护归档 |
| TTL 到期且未通过验证 | 标记"需验证" → 维护时二次确认：有效则续期，无效归档 |
| 技术过时（标注过时） | 标记 deprecated，保留历史 |

### 检索排序

经验检索时按 `effectiveness_score` 降序返回——高分经验优先展示，
低分经验自动靠后，避免"坏经验"误导新项目。

## 🔄 工作流

### 沉淀（写完经验）
```
触发时机：
1. 项目完成/阶段完成 → 回顾：有什么坑值得全局记？
2. 踩坑并解决 → 判断是否可复用（可复用 → 进全局库）
3. 发现成功模式 → 记录验证次数

动作：
1. 判断经验归属：
   - 单项目细节 → 项目 .snapshots/（snapshot-notes）
   - 个人角色视角 → agents/<角色>/EXPERIENCE.md（agent-ops）
   - 跨项目可复用 → 全局经验库（本 skill）🆕
2. 按模板写入 ~/.hermes/experience/pitfalls/ 或 patterns/
3. 更新 INDEX.md（加索引条目）
```

### 检索（复用经验）
```
1. 新项目遇到问题 → 先查全局经验库：
   grep -i "<关键词>" ~/.hermes/experience/pitfalls/ ~/.hermes/experience/patterns/
2. 命中 → 直接应用解法，不重复踩坑
3. 未命中 → 解决问题后按 §沉淀 记录（让下一个项目受益）
```

|----------|------|------|
| 单项目进度/状态 | `.snapshots/` | 这个项目 Phase 2 完成了 |

| 用户偏好 | Hermes 记忆 | 用户喜欢中文输出 |

## 6️⃣ 与全家桶衔接

| Skill | 协作关系 |
|-------|----------|
| `snapshot-notes` | 管项目内快照；项目完成时把可复用经验"提升"到全局库 |
| `agent-ops` | 管个人工位经验；工位里的通用坑可"提升"到全局库 |
| `project-init` | 新项目计划时先查全局经验库，把已知坑写进计划风险段 |
| `dev-team` | 团队开发时主Agent 定期把项目经验沉淀到全局库 |
| `agent-ops` | 自动循环中每次踩坑解决 → 判断是否入全局库 |

## ⚠️ 核心原则

1. **可复用才入全局**：只存跨项目通用的，单项目细节留在快照。
2. **经验要验证**：PATTERN 记录验证次数；未验证的标注"待验证"。
3. **索引必更新**：写入经验后必须更新 INDEX.md，否则检索不到。
4. **定期整理**：每月回顾，合并重复、清理过时。
5. **避免膨胀**：经验库不是日志，只存高价值、可复用的。

## 快速排障

| 症状 | 处理 |
|------|------|
| 找不到经验 | 检查 INDEX.md 标签是否更新；grep 关键词放宽 |
| 经验重复 | 合并到最完整的一条，更新 INDEX |
| 单项目细节混入全局 | 移回项目 .snapshots/，全局只留通用 |
| 经验过时 | 标记 deprecated，保留历史供参考 |
