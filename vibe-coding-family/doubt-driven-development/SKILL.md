# Doubt-Driven Development（怀疑驱动开发）

**来源**：addyosmani/agent-skills（Production-grade engineering skills）。
**定位**：`open-code-review` 是**事后**审查（写完才审）；本 skill 是**飞行中**交叉质询——
长会话里假设会悄悄变成"事实"，怀疑循环用**新鲜上下文**把它们拽回"待验证"。

## 1️⃣ 五步怀疑循环

```
CLAIM ──→ EXTRACT ──→ DOUBT ──→ RECONCILE ──→ STOP
声明      提取假设     新鲜对抗      调和验证      停止条件
```

| 步 | 动作 | 例 |
|----|------|-----|
| **CLAIM** | 明确当前决策/结论 | "这个接口用 POST 就行" |
| **EXTRACT** | 列出它依赖的**假设**（显式+隐式） | "后端接受 POST" / "无 CSRF" / "只有内网用" |
| **DOUBT** | 用**新鲜上下文**对抗每条假设（见 §2） | 委派无会话历史的子 agent 审："这个假设成立吗？" |
| **RECONCILE** | 验证：假设仍成立→记录；不成立→修正决策 | 发现 CSRF 风险 → 改用带 token 的方案 |
| **STOP** | 停止条件（见 §3），循环不无限 | 全部假设验证过 + 无新质疑 |

## 2️⃣ 新鲜上下文对抗（核心机制）

> **长会话毒化**：会话越久，早期假设越被当作"事实"（上下文压缩/惯性/共识感）。
> 对抗方法 = **找没见过这段对话的人/agent 来质疑**。

**落地（全家桶版）**——用 `delegate_task` 委派一个**无当前会话上下文**的子 agent：
```
委派目标: "这是决策 <X>, 请以全新视角质疑: 哪些假设可能不成立? 缺了什么信息?"
委派上下文: 只给决策摘要 + 相关代码/文档(不给整个会话历史)
委派验收: 返回 N 条质疑 + 每条的依据
```
- 子 agent 没有你的会话惯性 → 天然新鲜视角
- 只喂必要上下文 → 不重复整个会话

**人工版**：向用户复述"我现在的假设是 X，它对吗？"（一次一个，不堆砌）。

## 3️⃣ 停止条件与判定标准

**什么时候该 DOUBT（非平凡决策判定）**：
| 信号 | 判定 |
|------|------|
| 影响 >1 个模块 / 对外接口 / 数据格式 | 非平凡 → 必过怀疑循环 |
| 依赖未验证的外部假设（API 行为/平台特性） | 必过 |
| 连续 3 次成功后的自满点 | 必过（防惯性） |
| 纯展示/文案/一行常量 | 平凡 → 跳过 |

**STOP 条件（循环不无限）**：
- 每条假设都验证过（成立/修正/废弃）
- 新鲜视角无新质疑（质疑数收敛）
- 最多 2 轮对抗（2 轮后仍争议 → 升级给人决定）

## 4️⃣ 破局技法库（v1.1 新增 — claudekit problem-solving 精华）

怀疑循环卡住「不是假设错，而是没思路」时，按 stuck 类型分发到以下技法（每个只试一轮，别连环套用）：

| 卡住类型 | 技法 | 一句话动作 |
|----------|------|-----------|
| 常规方法都试过没用 | **Collision-Zone** 碰撞思考 | 强制把不相干概念拼一起："把 X 当 Y 处理会怎样？"（如"把发布流程当游戏存档系统设计"） |
| 被"只能这样"绑架 | **Inversion** 反转假设 | 翻核心假设："如果反过来才对呢？"（如"先写测试"→"先删测试"）——翻出来的是隐藏约束，不一定要照做 |
| 似曾相识的困境 | **Meta-Pattern** 元模式 | 3+ 个领域出现同一模式 = 通用原则（如"缓冲池/队列/缓存"都是削峰填谷） |
| 不确定可扩展性 | **Scale Game** 极端尺度 | 放大/缩小 1000 倍测试：1 用户→100 万用户，现在隐藏的真相会显形 |
| 复杂度螺旋上升 | **Simplification Cascades** 简化级联 | 找一个洞察让多个组件变多余："如果 X 成立，我们就不需要 Y、Z" |
| 说不清怎么卡住的 | 回 §3 STOP 判定 | 先分清"假设错了"（怀疑循环）还是"没思路"（本表），别混用 |

> 与怀疑循环分工：DOUBT 管「假设错了」；本表管「思路枯竭」。先诊断 stuck 类型再选工具。

## 5️⃣ 与全家桶衔接

| Skill | 分工 |
|-------|------|
| `open-code-review` / `code-review` | **事后**审查（写完后）；本 skill **飞行中**（写完前） |
| `delegate_task` | 新鲜上下文对抗的执行通道（委派无历史子 agent） |
| `requirement-clarify` | 需求阶段"问清楚"；本 skill 实现阶段"质疑假设" |
| `snapshot-notes` | 假设验证结果记快照，防下次会话重复怀疑 |

## 6️⃣ 快速排障

| 症状 | 处理 |
|------|------|
| 循环停不下来 | STOP 条件：2 轮上限 + 收敛判定 |
| 子 agent 没新视角 | 只喂决策摘要+必要文件（喂太多=带着你的惯性） |
| 质疑都是废话 | 过滤：只处理"有依据的质疑"（能指出具体风险/缺信息） |
| 怕麻烦跳过 | 记住：怀疑一次 ≈ 事后返工 1/10 成本（防患于未然） |
