# 自动开发指挥循环（Agent Loop）

**核心闭环**：派发任务 → 子Agent工作 → **汇报** → 主Agent**审查+指挥** → 继续循环。
配合用户路由规则，实现**无人自动开发**（能自动就自动，该问就问）。

```
┌──────────────────────────────────────────────────────┐
│                主Agent（指挥循环）                      │
│  ┌─────────┐   ┌─────────┐   ┌──────────────┐        │
│  │ 派发任务  │ → │ 子Agent  │ → │ 汇报(Report)  │        │
│  └─────────┘   │  工作    │   └──────┬───────┘        │
│       ↑        └─────────┘          │                │
│       │              审查+指挥决策   ▼                │
│  ┌─────────┐   ┌──────────────┐   ┌──────────┐      │
│  │ 继续/退回│ ← │  用户路由检查  │ ← │ 状态判定   │      │
│  │ 新任务   │   │ 定期汇报/询问  │   └──────────┘      │
│  └─────────┘   └──────────────┘                      │
└──────────────────────────────────────────────────────┘
```

## 1️⃣ 子Agent 汇报格式（Report 块）— 强制

每个子Agent 工作结束，**必须**在输出末尾附统一汇报块。主Agent 以此指挥下一步。

```markdown
## 📤 工作汇报
- **任务**：<本次任务一句话>
- **状态**：✅完成 / ⚠️部分完成 / ❌失败 / 🛑阻塞
- **产出**：<文件/结果清单，含路径>
- **验证**：<如何验证的 + 真实结果，测试通过数等>
- **问题**：<遇到的问题与原因>
- **需主Agent决策**：<是/否 + 具体问题>
- **建议下一步**：<建议>
```

## 2️⃣ 主Agent 指挥决策表 — 状态驱动

| 汇报状态 | 指挥决策 | 具体动作 |
|---------|----------|----------|
| ✅ 完成+审查通过 | **继续** | 按计划派下一个任务（dev-team 下一 Phase） |
| ⚠️ 部分完成 | **评估** | 缺失可接受 → 继续；不可接受 → 退回补齐（附意见） |
| ❌ 失败 | **重试** | 保留原 context 重试，最多 2 次 |
| 🛑 阻塞（需用户） | **暂停+询问** | 走"重大难点/决策询问"路由 |
| ❌ 重试 2 次仍败 | **降级** | 换子Agent / 简化任务 / 询问用户 |
| 需主Agent决策 | **决策** | A级用户：自主决策；B/C级：给选项询问 |

## 3️⃣ 无人自动开发模式（Auto-Pilot）

**开启条件**：用户说"自动开发/无人值守/auto"；或 A 级（Vibe-coder）用户项目。

**自动循环规则**（主Agent 自主执行，不逐阶段等确认）：
```
Phase 0 → 1 → 2 → 3 → 4 → 5 自动推进
每轮：派发 → 收汇报 → 审查 → 决策 → 下一轮
```

**自动推进时的自主边界**（以下必须暂停问用户，见 §4）：
1. 技术选型变更（换框架/换数据库）
2. 需求范围变化（加/减功能）
3. 3 轮 Bug 循环仍失败的降级交付
4. 预算/时间线变化
5. 连续 3 次任务失败

**每轮循环的落盘**（保持可恢复）：
- 更新 `.snapshots/SNAPSHOT.md`（团队状态）
- 更新工位 `agents/<角色>/MEMORY.md + PLAN.md + EXPERIENCE.md`
- 更新计划 `.snapshots/plans/PLAN-<日期>.md` 状态

**停止条件**：项目完成 / 触发用户询问 / 用户打断 / 超过最大循环轮数。

## 4️⃣ 用户路由规则 — 什么时候联系用户

### 📢 定期汇报（不打断，主动通知）
| 时机 | 汇报内容 |
|------|----------|
| 每完成 1 个 Phase | 阶段简报：做了什么 + 下一步 |
| 每完成 3 个子任务 | 进度看板（dev-team 看板模板） |
| 长跑任务（>1小时） | 每 15 分钟进度摘要 |
| 项目完成 | 最终交付报告 |

汇报模板（简洁版）：
```markdown
📊 自动开发进度 | {项目名}
✅ 刚完成：<Phase X + 产出摘要>
🔄 进行中：<当前子Agent + 任务>
⏭ 下一步：<计划>
🛑 阻塞：<如有>
```

### ⚠️ 重大决策（必须询问用户）
| 触发条件 | 询问方式 |
|----------|----------|
| 技术选型变更 | 2-3 个选项 + 推荐 + 理由 |
| 需求范围变化 | 说明影响 + 选项 |
| 降级交付决策 | 3 方案（架构回退/功能裁剪/人工介入） |
| 预算/时间线变化 | 新方案 + 影响说明 |

### 🔥 重大难点（必须询问用户）
| 触发条件 | 处理 |
|----------|------|
| 同一任务连续失败 3 次 | 汇总失败原因 + 请用户给方向 |
| 阻塞超过 15 分钟 | 说明卡点 + 询问是否换方案 |
| 需求与实现严重冲突 | 摆出矛盾 + 请用户裁决 |
| 子Agent 异常（非预期） | 报告 + 询问是否继续 |

## 5️⃣ 与全家桶衔接

| Skill | 协作 |
|-------|------|
| `dev-team` | agent-loop 是其**外层循环控制器**：dev-team 管"一个阶段怎么做"，agent-loop 管"阶段之间怎么循环、怎么汇报" |
| `agent-workspace` | 每个子Agent 的工位（MEMORY/PLAN/EXPERIENCE）在循环中持续读写 |
| `snapshot-notes` | 每轮循环更新 `.snapshots/SNAPSHOT.md`，保证断点可恢复 |
| `plan-workflow` | 循环按 `.snapshots/plans/` 计划推进，完成一项勾一项 |
| `multi-agent-config-manager` | 深度研究场景也可套用循环（研究→汇报→指挥下一路） |

## 6️⃣ 使用方式

```bash
# 自动开发模式
"自动开发 <项目>" → 主Agent 加载 dev-team + agent-loop
                    → 自动循环 Phase 0-5，定期汇报，重大决策询问

# 手动指挥模式
"组队开发 <项目>" → 主Agent 每阶段结束汇报，等你确认再继续
                    → agent-loop 提供状态判定和决策支持

# 中途切换
"改成自动" / "暂停，等我确认" → 切换 Auto-Pilot 开关
```

## 7️⃣ 心跳检测（v1.1 新增 — 子Agent 无响应接管）

**目的**：子Agent 长时间无响应时，主Agent 自动接管，防止流程卡死。

| 场景 | 动作 |
|------|------|
| 子Agent 超 3 分钟无输出 | 发送心跳提醒（"仍在处理？预计还要多久？"） |
| 超 5 分钟无响应 | **主Agent 接管**：取消当前委派，记录异常快照 |
| 接管后 | 分析卡点（缺依赖/等外部/死循环）→ 修复或降级 → 重新委派 |
| 连续 2 次接管仍失败 | 激活 vibe-terminal-safe 安全模式 + 询问用户 |

**异常快照记录**（v1.2 起写入独立目录 + 通知用户）：

```markdown
# 异常记录 — <时间戳>
- 时间：<时间戳>
- 子Agent：<角色>
- 任务：<任务名>
- 无响应时长：<X 分钟>
- 接管动作：<重新委派/降级/暂停>
- 根因分析：<卡在哪>
- 建议：<重试 / 重新分配 / 人工介入>
```

文件路径：`.snapshots/agent-anomalies/YYYY-MM-DD-HHMM.md`（独立目录，便于汇总审计）。
有通知渠道时（Telegram/QQ 等），接管后同步发送异常摘要给用户。

**熔断器模式 v2.0**（v1.3 升级 — 三层状态机 + 处置矩阵）：

```
状态定义：
- CLOSED（正常）    ：子Agent 正常响应，心跳正常
- OPEN（熔断）      ：连续 3 次超时 / 1 次致命错误 → 停止调用，直接 fallback
- HALF-OPEN（探测） ：熔断后等待 5 分钟 → 发一个探测任务 → 成功则 CLOSED，失败回 OPEN
```

**超时分级**：
| 任务类型 | 告警阈值 | 熔断阈值 |
|----------|----------|----------|
| 快速任务（预期 <30s） | 60s | 90s |
| 中速任务（预期 1-5min） | 2x 预期 | 3x 预期 |
| 慢速任务（预期 >5min） | 每 2min 必须进度汇报 | 连续 2 次无汇报 |

**处置策略矩阵**：
| 错误类型 | 处置方式 | 报告内容 |
|----------|----------|----------|
| 网络超时 | 重试 1 次 → 仍失败标记工具不可用 | 工具名、超时时间、建议切换源 |
| 逻辑死循环 | 立即 kill，保留堆栈快照 | 最后 10 步执行路径、变量状态 |
| 内存/CPU 爆 | 立即 kill，记录资源峰值 | 峰值内存、触发代码位置 |
| 权限拒绝 | 不重试，转人工 | 请求的权限、当前身份 |

**报告消费**：
- 异常报告写入 `.snapshots/agent-anomalies/YYYY-MM-DD-HHMM.md`
- 有通知渠道时同步发送摘要给用户
- 每日汇总由 `vibe-skills-gov-patterns` 分析，输出《Agent 健康日报》

## 8️⃣ Agent 信任链（v1.4 新增 — 活得好不好，不只是活没活着）

**目的**：多 Agent 最大风险不是"某个 Agent 挂了"，而是"某个 Agent 安静地做错了"。

### 信任令牌（Trust Token）

- 每个子 Agent 实例持有令牌：身份 ID + 权限范围 + 时效 + 签名
- 委派时父 Agent 可选：**完全授权** 或 **降级授权**（只读 / 只写 test/ 目录）
- 子 Agent 超出令牌权限的操作 → 自动拦截并上报

### 结果验证三选一（委派时指定）

| 方式 | 做法 | 适用 |
|------|------|------|
| 回归验证 | 子 Agent 修改后，父 Agent 跑相关模块测试 → 通过则信任 | 常规任务 |
| 交叉验证 | 同一任务派两个子 Agent → 对比输出 → 一致则高信任，分歧则人工仲裁 | 高风险/关键逻辑 |
| 渐进验证 | 子 Agent 结果先应用到沙箱 → 父 Agent 验收 → 再合并主分支 | 核心链路 |

### 可信度评分（写入 agent-collab 日志）

- 记录：历史任务成功率、回归通过率、人工复核通过率
- 低可信度 Agent 的产出自动触发"增强验证"（三选二）
- 评分数据供 knowledge-extraction 复盘引用

> 心跳检测与 `vibe-terminal-safe` 安全模式联动：连续失败 → 降级到只读 + 等用户。

## ⚠️ 边界与安全

- **自动≠失控**：重大决策/难点必须暂停询问，这是硬性路由规则。
- **汇报必真实**：子Agent 汇报必须带验证结果（测试数/运行输出），主Agent 抽查。
- **循环有界**：设定最大轮数（默认 20 轮），防止无限循环。
- **可中断**：用户随时可以打断自动模式，主Agent 必须立即停下并汇报当前状态。
- **单控制面 + 受约束协作**：只有一个主Agent 最终把关；子Agent 之间允许平级协作，
  但必须遵守 `agent-collab` 三步协议（请求→响应→验证闭环），不得越权、不得冲突、最终验收仍归主Agent。
- **权限最小化**：子Agent 默认只读+任务内授权，敏感操作归主Agent；
  自动循环中任何越权/高危/密钥请求 → 立即暂停 + 走 `agent-permissions` 处置 + 询问用户。

## 快速排障

| 症状 | 处理 |
|------|------|
| 子Agent 不汇报 | 委派时强制要求 Report 块格式，缺失则退回 |
| 循环卡死 | 检查是否触发用户询问路由；超时则暂停汇报 |
| 汇报内容模糊 | 退回，要求带真实验证数据 |
| 用户长时间未回复询问 | 保存当前状态到快照，等回复后断点续传 |
