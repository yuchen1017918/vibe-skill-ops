# 需求澄清访谈（Requirement Clarify）

**核心思想**：vibe-coding 最大的返工源是"方向没对齐"——AI 以为懂了就开写，写完用户说不是想要的。
本 skill 在**编码前**主动访谈用户，穷尽决策分支，把模糊需求变成可执行的 DECISIONS.md。

> 与确认交互契约（hub v1.0+）的分工：
> - **确认 SLA** = 被动确认：Agent 列方案，用户点头/否决（执行中的兜底）
> - **本 skill** = 主动访谈：Agent 问出用户没说的（执行前的对齐）
> 两者不冲突：访谈产出的关键决策，最后用批量确认（确认 SLA 的批量型）一次收口。

## 🚨 触发时机

| 时机 | 说明 |
|------|------|
| 新功能/新项目（Triage L1 及以上） | 编码前强制过一轮 |
| 用户说"做个X"但细节模糊 | 主动启动，不闷头开写 |
| 需求来自二手转述（上级/文档/他人） | 必须澄清，转述必有信息损耗 |
| 改动涉及多模块/核心链路（L2） | 完整 3-5 轮；L1 可压缩到 1-2 轮 |

> L0（一行文案/调参数）**不启动**——杀鸡不用牛刀（联动 hub 的复杂度 Triage）。

## 🔄 访谈协议（3-5 轮，每轮 ≤4 题）

**轮次节奏**：Round 1-3 固定，Round 4+ 按答案分支。**每轮最多 4 个问题**，不疲劳轰炸；
用户回答后立即记录，不重复问。

### Round 1：目标与用户
1. 这个功能/项目**做什么**？（一句话）
2. **给谁用**？（终端用户/内部工具/自己）
3. 最核心的**使用场景**是？（什么时候、怎么用）
4. **成功标准**？做完后拿什么判断"成了"？

### Round 2：边界与范围
1. **明确不做**什么？（防止范围蔓延）
2. 有什么**依赖/前置**？（已有代码/第三方服务/数据）
3. **约束**？（时间/平台/合规/性能）
4. 需要**兼容**什么？（旧版本/其他系统/浏览器）

### Round 3：技术与验收
1. **技术栈**有要求吗？（有 → 记录；没有 → 给建议并确认）
2. **验收标准**？（可测试的具体行为）
3. 已知**风险**？（最难的部分/不确定的地方）
4. 有**参考**吗？（相似产品/竞品/已有代码）

### Round 4+：分支深挖（按需）
- 答案涉及"用户角色" → 追问角色权限/流程
- 答案涉及"数据" → 追问数据来源/格式/量级/隐私
- 答案涉及"第三方" → 追问接口/文档/密钥
- 出现矛盾 → 指出矛盾，请用户裁决（**不静默选一条**）

### 规模感知（防官僚）
- L1 任务：压缩到 Round 1 + 关键 Round 2，最多 1-2 轮
- 用户说"别问了直接做" → 停止访谈，按已答信息 + 合理假设执行，并在 DECISIONS.md 标注假设
- 用户用 `/skip` → 跳过当前轮，进入产物生成

## 📝 产物：DECISIONS.md

访谈结束（或用户叫停）后，写 `.snapshots/DECISIONS.md`（项目根，随 git 走）：

```markdown
# 需求决策 — <项目/功能>

## 目标
- 做什么：<一句话>
- 给谁用：<用户画像>
- 成功标准：<怎么判断成了>

## 边界
- 做：<范围清单>
- 不做：<明确排除项>
- 依赖：<前置条件>
- 约束：<时间/平台/合规/性能>

## 技术
- 技术栈：<选定 + 一句话理由>
- 参考：<相似产品/代码>

## 验收
- [ ] <可测试的验收标准 1>
- [ ] <可测试的验收标准 2>

## 假设（用户没答/叫停时）
- <假设内容>（待验证）

## 变更记录
| 日期 | 变更 | 原因 |
|------|------|------|
```

> 归档：DECISIONS.md 保留在 `.snapshots/`，与 SNAPSHOT.md（状态）、plans/（任务）并列。
> 关系：**DECISIONS.md 管"为什么" → SNAPSHOT.md 管"在哪" → PLAN-*.md 管"做什么"**。

## ⚠️ 核心原则

1. **先澄清后编码**：L1+ 任务不澄清就动手 = 赌博。
2. **不问废话**：每轮 ≤4 题，能查到的（技术栈默认值）不占用提问额度。
3. **矛盾必裁决**：答案冲突时指出并请用户定，不静默选一条（呼应 Karpathy 纪律）。
4. **尊重叫停**：用户说"别问了"立即停止，转假设并标注。
5. **决策留痕**：所有问题答案进 DECISIONS.md，跨会话可恢复。

## 快速排障

| 症状 | 处理 |
|------|------|
| 用户不耐烦 | 压缩轮次，只问 Round 1 + 关键项 |
| 用户说"随便" | 按默认值 + 合理假设，标注"待验证" |
| 问题答案矛盾 | 指出矛盾，列两个选项请用户选 |
| 访谈完仍模糊 | 多问一轮"最坏情况/边界场景"，通常能逼出关键约束 |
| DECISIONS.md 缺失 | 重新访谈或按 SNAPSHOT.md 关键决策段反向补 |
